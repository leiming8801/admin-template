# 如何编写 AGENTS.md

> **本质**：面向 AI 的**概要 + 索引**。只写 AI 无法从代码/配置推断的硬性规则与必要信息，其余一律链接到 SSOT 文档。
> **判断标准**：一段内容如果必须同步到另一个文件才能保持正确，它就不该写在这里，改放链接。

---

## 1. 篇幅红线

| 指标     | 阈值                                             |
| :------- | :----------------------------------------------- |
| 推荐行数 | 能少则少，通常 ≤ 200 行，无最低行数              |
| 绝对上限 | 500 行，超出即失控                               |
| 超限处理 | 把"手册型"内容（检查清单、详述、代码块）迁到 docs/，只留链接 |

---

## 2. 必备模块

| 模块           | 内容要求                                                             |
| :------------- | :------------------------------------------------------------------- |
| 项目概述       | 一句话说清项目类型、技术栈、用途                                     |
| 工程结构       | 目录与分层，指向已有正文，不复制全量文件树                           |
| 常用命令       | 安装 / 开发 / 构建 / 数据库 / lint 五个入口，精确可复制               |
| 核心约定       | 命名、异常处理、响应格式、权限模型等 AI 猜不出来的约定                |
| 环境与默认账户 | `.env` 变量表、默认账号（仅模板占位值）                              |
| 文档导航       | 每份 docs 一句话说明，避免 AI 过度探索                               |
| 安全红线       | 不超过两行摘要 + 指向 `operation-safety-rule`                        |
| 验收标准       | 改完代码用什么命令验证（build / lint / db:generate）                 |

---

## 3. 避坑清单

| 禁止               | 原因                                        | 正确做法                                   |
| :----------------- | :------------------------------------------ | :----------------------------------------- |
| 写成万字长文       | 超出上下文预算，关键内容被截断              | 详情迁 docs/，这里只留索引                 |
| 包含模糊指令       | "代码要规范"不可执行                        | "颜色必须用 Arco Token"                    |
| 写死本机绝对路径   | 换环境失效并泄露目录结构                    | 用相对工作区根的路径                       |
| 泄露敏感信息       | AGENTS.md 入 Git                            | 绝不写真实密钥、数据库密码                 |
| 过度探索引导       | 链接一堆不相关文档，降低任务完成率          | 只链当前任务真正需要的 SSOT                |
| 与 docs 重复维护   | 改一处漏一处                                | 重复段落改为链接                           |
| 与代码实际不符     | 规则说了但代码不是这样，AI 照文档写就出错    | 陈述前核对代码；冲突时更新文档            |

---

## 4. 检测方法（写完后必做）

| 方法         | 操作                                                             | 通过标准                             |
| :----------- | :--------------------------------------------------------------- | :----------------------------------- |
| 事实核对     | 逐条核对版本号、端口、命令、目录、权限码与代码 / 配置一致         | 无一条与实际不符                     |
| 总结验证     | 让 AI"把 AGENTS.md 里的启动命令和硬性规范原样输出"                | 能准确提取，无截断丢失               |
| 反向约束测试 | 故意提出违反规范的需求（如禁用 `<a-table>` 时要求用 a-table）     | AI 拒绝并指出违规                    |
| 命令实测     | 问"安装依赖并启动前后端"                                          | AI 输出 `pnpm install` / `pnpm dev` 而不自造 |

> 修改后需开启新会话或重启工具，加载变更才生效。

---

## 5. 审查既有 AGENTS.md 的核对项

- [ ] 行数是否在 200 行内？超限内容是否已迁 docs/
- [ ] 文中链接是否全部有效（无指向已删除文件的死链）
- [ ] 事实性声明（版本、端口、命令、模块列表、默认账号）与代码 / 配置一致
- [ ] 是否存在与 docs/ 或 `.qoder/rules` 重复维护的段落
- [ ] 必备模块是否齐全，缺失是有意还是遗漏
- [ ] 是否包含本机绝对路径或真实凭据

---

## 6. 维护原则

| 原则     | 说明                                                     |
| :------- | :------------------------------------------------------- |
| 从错误迭代 | AI 反复犯同类错误时，把修正补成一条明确规则             |
| 及时同步   | 架构变更、依赖升级后同一次改动内更新本文                 |
| 人工审核   | 禁止工具自动生成后直接提交，必须人工精简                 |
| 渐进沉淀   | 未深入分析的模块只留索引，不预填未经证实的细节           |
