# 文档同步：影子扶正

> **核心隐喻**：代码是事实，文档是影子。两者不一致时，先怀疑影子歪了。
> 本技能只回答两件事：**影子哪里歪了**（漂移检测）、**按什么规矩扶正**（最小修正）。不重写文档、不重排结构。

---

## 1. 铁律

| 铁律             | 说明                                                                 |
| :--------------- | :------------------------------------------------------------------- |
| 默认代码是事实   | 文档与代码冲突时改文档；数字、路径、名称逐字取自代码，禁止凭记忆填写   |
| 只修描述不重写   | 只改漂移的词句，不动周边句子、标题层级、章节顺序、详略密度            |
| 契约例外交人裁决 | 文档是既定约定而代码违背约定 → 可能是代码缺陷，单列"待确认"，不改文档迁就代码 |
| 推断不出就不动   | "为什么这样设计"等无法从代码验证的叙述保持原样，标注"待人工确认"       |
| 每处修改可审查   | 报告必须含"原文 → 代码事实 → 处理"对照，禁止静默批量替换              |
| 上游只读         | 外部系统 / 上游仓的契约文档只做向下的单向同步，禁止回写               |

---

## 2. 漂移类型

| # | 类型         | 判定特征                                                     | 本项目例子                                                     |
| :- | :----------- | :----------------------------------------------------------- | :------------------------------------------------------------- |
| 1 | 路径 / 名称  | 文档写的目录、文件、组件、方法在代码中不存在或已改名         | 文档写 `src/views/system/user`，实际是 `views/system/admin-user` |
| 2 | 接口         | 路径、方法、参数、返回结构与 `apps/web/src/api/` 实现不符     | 文档写 `GET /api/members`，实际 `GET /members`（全局前缀 `/api`） |
| 3 | 行为         | 默认值、边界、状态流转与实现不符                             | 文档写"状态 0 停用 1 启用"，代码枚举相反                       |
| 4 | 清单         | 权限码、菜单项、字段表有增减未同步                           | 新增了 `member:delete`，权限码清单没补                         |
| 5 | 结构         | 组件拆分、目录重组后文档仍写旧结构                           | 逻辑已抽到 hooks，文档仍写"在页面内"                            |
| 6 | 版本 / 依赖  | 文档写的版本与 `package.json` / lock 不符                    | 文档写 Arco 2.44，实际 2.55                                     |
| 7 | 幽灵描述     | 功能已删除或改名，文档仍在描述其用法                         | 写 newweb-conventions-rule 已删除但仍被引用                     |
| 8 | 未记录能力   | 代码已有但文档缺失                                           | 新增的 `formatDate` 用法文档未提                                |

> 类型 8 的扶正方式是**最小补记**（一句话或一行表项嵌入既有表格），不新增章节。

---

## 3. 检测流程

1. **圈定范围**：用户指定文档；或按本次代码变更反推关联文档（AGENTS.md、README.md、docs/、locale、seed.ts）
2. **提取可验证陈述**：只取事实性断言——路径、名称、参数、数值、行为、清单、版本；跳过目标性表述与观点
3. **逐条取证**：打开对应文件核对（路由、api 模块、store、组件 props、package.json、.env、seed.ts、i18n messages）。**必须打开文件，不能凭印象**
4. **分类处置**：

| 判定     | 处理                                             |
| :------- | :----------------------------------------------- |
| 一致     | 不动                                             |
| 漂移     | 按 §4 最小扶正                                   |
| 待确认   | 代码中找不到证据，或属设计意图叙述；不改，报告标注 |
| 契约违背 | 文档是既定约定而代码相反；不改，单列交用户裁决    |

---

## 4. 扶正规矩

- **最小改动**：替换漂移的词句即可，不改写整段、不调整格式、不顺手"优化"表述
- **同源漂移一次改齐**：同一事实写在多处（README + AGENTS.md + docs）时全部改齐并在报告逐条列出，同时提示"该事实多处维护，可收敛为单一来源"——只提示，不顺手重构
- **保持表达密度**：原文一句话就改一句话，原文表格一行就改一行
- **补记贴位**：新增能力补进既有表格 / 清单的对应位置，措辞仿照相邻条目
- **证据落名**：报告中写明证据文件与关键行为，便于复核
- 改完同步更新文档头部的 `updated` 字段

---

## 5. 报告格式

| # | 文档位置 | 原文 | 代码事实（证据） | 判定 | 处理 |
| :- | :------- | :--- | :--------------- | :--- | :--- |
| 1 | `AGENTS.md` §2 | 端口 3000 | `apps/server/.env` PORT=3000 | 一致 | 不动 |
| 2 | `docs/后端模块详解.md` §3 | 权限码 `system:user:view` | `seed.ts` 中同名权限码 | 一致 | 不动 |
| 3 | `docs/前端模块详解.md` §5 | 路由写死在 `routes/modules` | 实际走 `menuFromServer` 动态注册 | 漂移 | 已按代码改写该句 |
| 4 | `docs/数据库设计文档.md` | 提到 `RoleMenu` 表 | schema 中无此模型 | 待确认 | 未改，请人工确认 |

> 汇总：漂移扶正 N 处 · 待人工确认 N 处 · 契约违背 N 处（待裁决）· 同源收敛建议 N 条

## 6. 自查清单

- [ ] 每处修改都有代码证据（文件 + 行为），没有凭记忆填数字或路径
- [ ] 只改了漂移陈述，未重写段落、未调整章节结构与语气
- [ ] 契约违背项保持原样并已单独报告
- [ ] 报告含"原文 → 代码事实 → 处理"完整对照
- [ ] 同源漂移已在所有位置一次改齐
- [ ] 无法验证的陈述未改动，已标注"待人工确认"
- [ ] 全程仅向下同步，未写入任何上游文档
