# 数据库设计文档

> 本文档详细说明 Admin Template 的数据库表结构、ER 关系、字段定义与设计约定。

## 1. 数据库概览

- **数据库**：MySQL 8.0+
- **字符集**：utf8mb4 + utf8mb4_unicode_ci
- **ORM**：Prisma 5+
- **Schema 文件**：`apps/server/prisma/schema.prisma`
- **数据库名**：`admin_template`

共 8 张表，分为四组：

| 组 | 表名 | 说明 |
|---|---|---|
| RBAC 权限体系 | `admin_user` | 后台管理员 |
| | `role` | 角色 |
| | `permission` | 权限（菜单/按钮/API，树形） |
| | `admin_user_role` | 用户-角色关联（多对多） |
| | `role_permission` | 角色-权限关联（多对多） |
| 认证会话 | `admin_session` | 后台登录会话与 Refresh Token 哈希 |
| 会员管理 | `member` | 前台会员（独立于 RBAC） |
| 文件存储 | `file_object` | 本地文件元数据与归属 |

## 3. 表结构详解

### 3.1 admin_user — 后台管理员

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | Int | PK, auto_increment | 主键 |
| `username` | VARCHAR(50) | UNIQUE, NOT NULL | 登录用户名 |
| `password` | VARCHAR(255) | NOT NULL | bcrypt 加密密码 |
| `nickname` | VARCHAR(50) | NOT NULL | 昵称 |
| `email` | VARCHAR(100) | UNIQUE | 邮箱 |
| `phone` | VARCHAR(20) | | 手机号 |
| `avatar` | VARCHAR(500) | | 头像 URL |
| `status` | TINYINT | DEFAULT 1 | 0=禁用 1=启用 |
| `lastLoginAt` | DateTime | | 最后登录时间 |
| `lastLoginIp` | VARCHAR(50) | | 最后登录 IP |
| `remark` | VARCHAR(500) | | 备注 |
| `createdAt` | DateTime | DEFAULT now() | 创建时间 |
| `updatedAt` | DateTime | auto updatedAt | 更新时间 |

**关联**：通过 `admin_user_role` 表与 `role` 多对多关联；与 `admin_session` 一对多关联，删除用户时级联删除会话。

**Prisma 模型**：`AdminUser`，表名映射 `@@map("admin_user")`。

### 3.2 role — 角色

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | Int | PK, auto_increment | 主键 |
| `name` | VARCHAR(50) | UNIQUE, NOT NULL | 角色名称 |
| `code` | VARCHAR(50) | UNIQUE, NOT NULL | 角色编码（如 `super_admin`） |
| `sort` | Int | DEFAULT 0 | 排序值 |
| `status` | TINYINT | DEFAULT 1 | 0=禁用 1=启用 |
| `remark` | VARCHAR(500) | | 备注 |
| `createdAt` | DateTime | DEFAULT now() | 创建时间 |
| `updatedAt` | DateTime | auto updatedAt | 更新时间 |

**关联**：
- 通过 `admin_user_role` 与 `AdminUser` 多对多
- 通过 `role_permission` 与 `Permission` 多对多

**Prisma 模型**：`Role`，表名映射 `@@map("role")`。

### 3.3 permission — 权限（树形结构）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | Int | PK, auto_increment | 主键 |
| `parentId` | Int | DEFAULT 0, map("parent_id") | 父 ID，0=根节点 |
| `name` | VARCHAR(100) | NOT NULL | 权限名称，存 i18n key（如 `menu.system.adminUser`） |
| `type` | TINYINT | NOT NULL | 1=菜单 2=按钮 3=API |
| `permission` | VARCHAR(100) | | 权限标识（如 `system:user:add`） |
| `path` | VARCHAR(200) | | 前端路由路径（菜单类型） |
| `component` | VARCHAR(200) | | 前端组件路径（菜单类型） |
| `icon` | VARCHAR(50) | | 菜单图标，存 Lucide 官方 kebab-case 名（如 `layout-dashboard`、`users`），无前缀；需在 `apps/web/src/utils/icons.ts` 的 `menuIconMap` 中注册后方可渲染 |
| `sort` | Int | DEFAULT 0 | 排序值 |
| `visible` | TINYINT | DEFAULT 1 | 0=隐藏 1=显示（菜单类型） |
| `createdAt` | DateTime | DEFAULT now() | 创建时间 |
| `updatedAt` | DateTime | auto updatedAt | 更新时间 |

**关联**：通过 `role_permission` 与 `Role` 多对多。`parentId` 自关联形成树形结构。

**设计要点**：
- `name` 字段存储 i18n key，前端通过 `t()` 翻译为对应语言；无翻译时直接显示原文
- `type` 区分三种权限粒度：菜单（路由级）、按钮（元素级）、API（接口级）
- `permission` 字段为权限码，后端 `@RequirePermission` 和前端 `v-permission` 均使用此值
- `path` + `component` 用于前端动态路由注册

**Prisma 模型**：`Permission`，表名映射 `@@map("permission")`。

### 3.4 admin_user_role — 用户-角色关联

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | Int | PK, auto_increment | 主键 |
| `userId` | Int | map("user_id"), FK→admin_user.id | 用户 ID |
| `roleId` | Int | map("role_id"), FK→role.id | 角色 ID |

**约束**：`@@unique([userId, roleId])` 防止重复关联。
**级联删除**：`onDelete: Cascade`，删除用户或角色时自动清理关联。

**Prisma 模型**：`AdminUserRole`，表名映射 `@@map("admin_user_role")`。

### 3.5 role_permission — 角色-权限关联

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | Int | PK, auto_increment | 主键 |
| `roleId` | Int | map("role_id"), FK→role.id | 角色 ID |
| `permissionId` | Int | map("permission_id"), FK→permission.id | 权限 ID |

**约束**：`@@unique([roleId, permissionId])` 防止重复关联。
**级联删除**：`onDelete: Cascade`，删除角色或权限时自动清理关联。

**Prisma 模型**：`RolePermission`，表名映射 `@@map("role_permission")`。

### 3.6 member — 前台会员

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | Int | PK, auto_increment | 主键 |
| `username` | VARCHAR(50) | UNIQUE | 用户名 |
| `nickname` | VARCHAR(50) | | 昵称 |
| `phone` | VARCHAR(20) | UNIQUE | 手机号 |
| `email` | VARCHAR(100) | UNIQUE | 邮箱 |
| `avatar` | VARCHAR(500) | | 头像 URL |
| `password` | VARCHAR(255) | NOT NULL | bcrypt 加密密码 |
| `gender` | TINYINT | | 0=未知 1=男 2=女 |
| `status` | TINYINT | DEFAULT 1 | 0=禁用 1=启用 |
| `lastLoginAt` | DateTime | | 最后登录时间 |
| `lastLoginIp` | VARCHAR(50) | | 最后登录 IP |
| `remark` | VARCHAR(500) | | 备注 |
| `createdAt` | DateTime | DEFAULT now() | 创建时间 |
| `updatedAt` | DateTime | auto updatedAt | 更新时间 |

**设计要点**：
- **独立于 RBAC 体系**：不参与角色和权限分配
- **已具备 C端认证字段**：`password`（bcrypt）、`status`、`lastLoginAt`，后续扩展 C端认证无需额外建表
- **C端 JWT 隔离**：会员 JWT 使用独立密钥（`JWT_MEMBER_SECRET`），与管理员 JWT 互不通用

**Prisma 模型**：`Member`，表名映射 `@@map("member")`。

### 3.7 admin_session — 后台登录会话

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | CHAR(36) | PK, UUID | 会话 ID，同时写入 JWT `sid` |
| `user_id` | Int | FK→admin_user.id, INDEX | 用户 ID |
| `refresh_token_hash` | CHAR(64) | NOT NULL | 当前 Refresh Token 的 SHA-256 哈希，不保存明文 |
| `expires_at` | DateTime | NOT NULL, INDEX | 会话固定过期时间，刷新不延长 |
| `revoked_at` | DateTime | | 撤销时间，空表示未撤销 |
| `revoked_reason` | VARCHAR(32) | | `logout` / `password_changed` / `password_reset` / `user_disabled` / `refresh_reused` |
| `last_used_at` | DateTime | | 最近登录或轮换时间 |
| `created_at` | DateTime | DEFAULT now() | 创建时间 |
| `updated_at` | DateTime | auto updatedAt | 更新时间 |

**设计要点**：每次刷新原子替换 Token 哈希；旧 Token 重放时撤销会话。删除用户时 `onDelete: Cascade` 清理会话，过期和撤销记录由后续清理任务按需删除。

**Prisma 模型**：`AdminSession`，表名映射 `@@map("admin_session")`。

### 3.8 file_object — 本地文件元数据

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | Int | PK, AUTO_INCREMENT | 文件 ID |
| `owner_type` | VARCHAR(20) | NOT NULL, INDEX | 归属类型：`admin` / `member` |
| `owner_id` | Int | NOT NULL, INDEX | 归属用户 ID |
| `purpose` | VARCHAR(30) | NOT NULL | 用途：`avatar` / `file` |
| `object_key` | VARCHAR(500) | UNIQUE, NOT NULL | 本地存储相对路径，磁盘文件名为 UUID |
| `original_name` | VARCHAR(255) | NOT NULL | 原始文件名 |
| `mime_type` | VARCHAR(100) | NOT NULL | 响应 Content-Type |
| `extension` | VARCHAR(20) | NOT NULL | 扩展名（不含点） |
| `size` | Int | NOT NULL | 字节数 |
| `created_at` | DateTime | DEFAULT now() | 上传时间 |

**设计要点**：`owner_type + owner_id` 是逻辑归属，不设置跨表外键；普通文件下载和删除必须校验归属，实际文件保存在 `apps/server/storage/uploads/`。

**Prisma 模型**：`FileObject`，表名映射 `@@map("file_object")`。

### 6.3 执行行为（幂等增量）

`pnpm db:seed` 可重复执行，不会清库：

| 环节 | 行为 |
|---|---|
| 管理员 / 角色 / 会员 | 按 `username` / `code` 查找，不存在才创建 |
| 权限 | 按 `name` 查找（该列无唯一约束，用 findFirst + update / create），存在则覆盖 type/path/component/icon/sort/visible |
| 父子关系 | 第二轮按 `parentName` 重建 `parentId` |
| 角色授权 | `rolePermission.createMany({ skipDuplicates: true })`，只补缺不删除 |

因此重跑 seed 只同步代码中定义的条目：管理员手动新建的权限会保留，其他角色已有的授权也不会丢失。

## 7. 数据库操作命令

```bash
# 查看迁移状态
pnpm db:migrate:status

# 开发环境根据 Schema 生成并应用迁移（会写开发数据库）
pnpm db:migrate:dev

# 新环境、测试和生产执行已提交迁移
pnpm db:migrate:deploy

# 生成 Prisma Client
pnpm db:generate

# 临时原型直接同步 Schema（不生成迁移，禁止用于生产）
pnpm db:push

# 独立填充种子数据
pnpm db:seed
```

**注意事项**：
- 正式修改 `schema.prisma` 后使用 `pnpm db:migrate:dev`，并提交生成的 `apps/server/prisma/migrations/`
- `db:migrate:deploy` 只执行尚未应用的迁移，不生成新迁移，也不自动执行 Seed
- `db:push` 仅用于临时原型，不作为正式结构变更和生产升级方式
- 已由 `db push` 创建的既有数据库必须先按《部署与运维指南》§5.5 核对 drift 并基线化，不能直接重复执行 `0_init`
- 禁止使用 `prisma migrate reset` 或 `db push --force-reset` 处理正常升级

## 8. Prisma Client 使用

后端通过 `PrismaService`（全局注入）操作数据库：

```typescript
// 在 Service 中注入
constructor(private readonly prisma: PrismaService) {}

// 查询用户（含关联）
const user = await this.prisma.adminUser.findUnique({
  where: { id: userId },
  include: {
    roles: {
      where: { role: { status: 1 } },
      include: {
        role: {
          include: {
            permissions: { include: { permission: true } },
          },
        },
      },
    },
  },
});
```

字段映射约定：Prisma 模型使用 camelCase（如 `parentId`），数据库列使用 snake_case（如 `parent_id`），通过 `@map` 映射。
