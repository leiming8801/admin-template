# 前端模块详解

> 本文档详细说明 Vue3 前端各模块的职责、文件结构、核心实现与关键逻辑。

## 1. 启动入口

### 1.1 main.ts

文件路径：`apps/web/src/main.ts`

启动流程：

1. 注册 Vue 插件：Arco Design（组件）、VxeTable（表格 UI）、Pinia、Vue Router、vue-i18n、全局组件、自定义指令（图标为按需 import 的 Lucide 组件，不走全局注册）
2. VxeTable 国际化：注册 zh-CN / en-US 语言包，读取 localStorage 中的 `arco-locale` 初始化语言
3. 主题初始化：读取 localStorage 中的 `arco-theme`，设置 VxeTable 暗色主题属性
4. 导入全局样式（`global.less`）和 Axios 拦截器（`api/interceptor.ts`）
5. 挂载应用

### 1.2 App.vue

文件路径：`apps/web/src/App.vue`

- 使用 Arco Design 的 `ConfigProvider` 包裹根组件，实现组件库语言跟随项目 locale
- 使用 Vue Router 的 `router-view` 渲染路由

### 1.3 应用配置

文件路径：`apps/web/src/config/settings.json`

```json
{
  "theme": "light",
  "navbar": true,
  "menu": true,
  "menuCollapse": false,
  "footer": true,
  "themeColor": "#165DFF",
  "menuWidth": 220,
  "globalSettings": false,
  "device": "desktop",
```

关键配置：`menuFromServer: true` 表示路由从后端动态获取，不在前端静态注册。

## 2. api/ — 请求封装

### 2.1 拦截器（interceptor.ts）

文件路径：`apps/web/src/api/interceptor.ts`

这是前端最核心的文件之一，负责所有 HTTP 请求的统一处理。`VITE_API_BASE_URL` 配置后端服务源地址且不包含 `/api`，留空时使用同源 Vite/Nginx 代理。

#### 请求拦截器

```
每个请求 → 注入 Authorization: Bearer {accessToken}
        → 注入 Accept-Language: {当前语言}
```

#### 响应拦截器

```
HTTP 200 + 业务 code 200 → 返回响应信封中的 data（业务数据 T）
HTTP 200 + 业务 code != 200 → Message.error 提示 → reject
  → code=401 且非登录接口 → 跳转登录页

HTTP 401（HTTP 层）
  → 登录接口的 401 → 弹提示，交给组件处理
  → 其他接口的 401 → 尝试 refreshToken 刷新（每个请求最多重试一次）
    → isRefreshing=false → 开始刷新 → 成功重发 / 失败跳登录
    → isRefreshing=true → 排队等待刷新结果

HTTP 403 → Message.error 提示无权限
其他错误 → Message.error 提示
```

**并发刷新处理**：使用 `isRefreshing` 标志和 `pendingRequests` 队列，确保单个页面内多个请求同时 401 时只刷新一次 token。刷新成功后必须同时替换 localStorage 中的 accessToken 和 refreshToken，再重发请求。业务 API 统一通过 `httpClient` 请求，成功时直接返回业务数据 `T`；刷新接口使用独立 Axios 实例解析原始响应信封。

## 3. router/ — 路由系统

### 3.1 路由定义

文件路径：`apps/web/src/router/index.ts`

- 使用 `createWebHistory` 模式
- 静态路由仅注册：根路径重定向到 login、login 页、redirect 页、404 页
- `menuFromServer: true` 时不注册静态路由模块，避免与动态路由名称冲突

### 3.2 路由守卫

文件路径：`apps/web/src/router/guard/index.ts`

注册三个守卫（按执行顺序）：

| 守卫 | 文件 | 职责 |
|---|---|---|
| 页面守卫 | `index.ts` | emit 路由变化事件 |
| 用户登录守卫 | `userLoginInfo.ts` | 检查登录状态 + 获取用户信息 + 动态路由注册 |
| 权限守卫 | `permission.ts` | 校验路由访问权限 |

#### 用户登录守卫（userLoginInfo.ts）

```
路由进入 → NProgress.start()
  → isLogin()（localStorage 有 token）
    → 是 → userStore.role 已有值？
      → 是 → 目标是 login？重定向到首页 : 放行
      → 否 → userStore.info() 获取用户信息
           → appStore.fetchServerMenuConfig() 获取菜单
           → router.addRoute() 动态注册路由
           → 目标是 login？重定向到首页 : 重新触发导航（确保动态路由生效）
           → 异常 → logout → 跳转 login
    → 否 → 目标是 login？放行 : 跳转 login（带 redirect 参数）
```

#### 权限守卫（permission.ts）

```
路由进入 → Permission.accessRouter(to) 校验权限
  → menuFromServer 模式：
    → 菜单未加载？fetchServerMenuConfig()
    → 检查目标路由是否在服务端菜单中
    → 存在且有权限 → 放行
    → 不存在或无权限 → 跳转 404
  → 非 menuFromServer 模式：
    → 有权限 → 放行
    → 无权限 → 找第一个有权限的路由 / 404
```

### 3.4 菜单转路由

文件路径：`apps/web/src/utils/menu-to-route.ts`

核心函数 `transformMenusToRoutes(menus: MenuItem[]): RouteRecordRaw[]`

将后端返回的菜单树转换为 Vue Router 路由记录：

| 菜单字段 | 路由字段 | 说明 |
|---|---|---|
| `path` | `path` | 路由路径 |
| `component` | `component` | 通过 `import.meta.glob('@/views/**/*.vue')` 懒加载 |
| `name` (i18n key) | `meta.locale` | 菜单标题，前端 `t()` 翻译 |
| `icon` | `meta.icon` | 菜单图标 |
| `children` | `children` | 递归转换 |

**特殊处理**：

- 一级菜单使用 `DEFAULT_LAYOUT` 作为容器组件
- 一级菜单有 component 但无 children 时，添加默认子路由 + `hideChildrenInMenu`
- 路由名称从 i18n key 生成（如 `menu.system.adminUser` → `SystemAdminUser`）

### 3.5 客户端菜单

文件路径：`apps/web/src/router/app-menus/index.ts`

聚合 `routes/modules/` 和 `routes/externalModules/` 中的静态路由，供菜单组件渲染。在 `menuFromServer` 模式下主要使用服务端菜单。

## 4. store/ — Pinia 状态管理

### 4.1 useUserStore — 用户状态

文件路径：`apps/web/src/store/modules/user/index.ts`

| State | 类型 | 说明 |
|---|---|---|
| `id` / `username` / `nickname` / `avatar` | 基础信息 | 用户基本信息 |
| `roles` | `string[]` | 角色编码列表（如 `['super_admin']`） |

|---|---|

### usePermission 核心逻辑

```typescript
accessRouter(route) {
  // 不需要认证 → 放行
  // meta.roles 包含 '*' → 放行
  // super_admin → 放行
  // meta.roles 有值 → 检查角色匹配
  // meta.requiresPermission 有值 → 检查权限码
  // 无限制 → 放行

```

## 6. directive/ — 自定义指令

### v-permission — 按钮级权限指令

文件路径：`apps/web/src/directive/permission/index.ts`

```vue
<!-- 单个权限码 -->
<a-button v-permission="'system:user:add'">新增</a-button>

<!-- 多个权限码（满足任一即可） -->
<a-button v-permission="['system:user:edit', 'system:user:delete']">更多</a-button>
```

执行逻辑：

1. 读取指令绑定的权限码（支持字符串或数组）
2. `super_admin` 角色直接通过
3. 检查是否拥有任一所需权限码
4. 无权限 → 从 DOM 移除元素（`el.parentNode.removeChild(el)`）
5. 在 `mounted` 和 `updated` 钩子中均执行检查

### 图标方案（Lucide 单一来源）

全站图标统一来自 `@lucide/vue`（官方 Vue 包，`tree-shakable`），不再使用 IconPark 与 Arco 图标。`main.ts` 不注册任何全局图标组件，页面内按需 `import` 后直接用：

```vue
<script lang="ts" setup>
  import { Plus } from '@lucide/vue';
</script>

<template>
  <a-button type="primary">
    <template #icon><Plus :size="16" /></template>
    新增
  </a-button>
</template>
```

菜单图标走「字符串 → 组件」桥接，链路如下：

| 环节 | 位置 | 说明 |
|---|---|---|
| 存储 | `apps/server/prisma/seed.ts` 的 `icon` 字段 | Lucide 官方 kebab-case 名，如 `layout-dashboard`、`users`，无前缀 |
| 白名单 | `apps/web/src/utils/icons.ts` 的 `menuIconMap` | 显式 import 的 31 个图标，保持 tree-shaking 生效 |
| 解析 | `resolveMenuIcon(name)` | 命中返回组件，未命中返回 `null`（菜单按无图标渲染） |
| 渲染 | `components/menu/index.vue` | `h(component, { size: 16 })` 渲染；尺寸必须在渲染处传，Lucide 默认 24 且 class 为 `.lucide`（无 `.lucide-icon`） |

> 禁止 `import * as icons from '@lucide/vue'` 后动态索引：会把全部 7000+ 图标打进产物。新增图标需先在 https://lucide.dev/icons 确认名称存在，再在 `menuIconMap` 注册（权限表单下拉选项与白名单同源）。
