# 后端模块详解

> 本文档详细说明 NestJS 后端各模块的职责、文件结构、核心实现与接口清单。

## 1. 启动入口与根模块

### 1.1 main.ts — 启动入口

文件路径：`apps/server/src/main.ts`

职责：

| 配置项 | 说明 |
|---|---|
| CORS | 允许 `http://localhost:5173` 跨域，支持 credentials |
| 全局前缀 | 所有路由以 `/api` 开头 |
| ValidationPipe | DTO 自动校验，`whitelist: true` + `transform: true` |
| TransformInterceptor | 全局响应拦截器，包装返回值为 `{ code, message, data }` |
| Swagger | `/docs` 路径提供 API 文档，支持 Bearer Token 认证 |

### 1.2 app.module.ts — 根模块

文件路径：`apps/server/src/app.module.ts`

注册内容：

```
imports:
  ConfigModule.forRoot()   → 环境变量加载与启动校验
  I18nModule.forRoot()     → 后端多语言
  PrismaModule              → 全局 PrismaClient
  AuthModule                → 认证模块
  SystemModule              → 系统管理模块
  MemberModule              → 会员管理模块
  DashboardModule           → 工作台模块

providers (全局):
  APP_FILTER → AllExceptionsFilter  → 全局异常过滤器
  APP_GUARD  → JwtAuthGuard         → 全局 JWT 认证守卫
  APP_GUARD  → PermissionGuard      → 全局权限守卫
```

### 1.3 config/index.ts — 环境变量配置

文件路径：`apps/server/src/config/index.ts`

`ConfigModule` 统一加载 `.env`，`config/validation.ts` 在启动时校验必填项、密钥长度与有效期格式；`index.ts` 以配置工厂提供类型化配置，各模块通过 `ConfigService` 读取。JWT 密钥不再提供默认值，示例开发密钥在生产环境会被拒绝。

## 2. common/ — 横切关注点

### 2.1 装饰器（decorators/）

| 装饰器 | 文件 | 作用 |
|---|---|---|
| `@Public()` | `public.decorator.ts` | 标记接口为公开访问，跳过 JWT 守卫 |
| `@RequirePermission(...codes)` | `require-permission.decorator.ts` | 声明接口所需的权限码，配合 PermissionGuard 校验 |
| `@CurrentUser()` | `current-user.decorator.ts` | 从 `request.user` 提取当前登录用户信息（JwtPayload） |

**JwtPayload 结构**：

```typescript
interface JwtPayload {
  sub: number;        // 用户 ID
  username: string;
  type: 'access' | 'refresh';
  scope?: string;     // 'admin' | 'member'
}
```

### 2.2 守卫（guards/）

#### JwtAuthGuard — JWT 认证守卫

文件路径：`apps/server/src/common/guards/jwt-auth.guard.ts`

- 继承 `AuthGuard('jwt')`，使用 Passport JWT 策略
- 通过 Reflector 读取 `@Public()` 元数据，标记为公开的接口直接放行
- 认证失败抛 `UnauthorizedException('auth.tokenExpired')`

执行流程：

```
请求进入 → 读取 @Public() 元数据
  → 有 @Public() → 放行
  → 无 @Public() → 调用 Passport JWT 策略验证 token
    → 验证成功 → 挂载 request.user → 放行
    → 验证失败 → 抛 401 UnauthorizedException
```

#### PermissionGuard — 权限守卫

文件路径：`apps/server/src/common/guards/permission.guard.ts`

- 通过 Reflector 读取 `@RequirePermission()` 元数据
- 无装饰器 → 直接放行
- 有装饰器 → 查询用户角色和权限码
  - `super_admin` 角色 → 直接放行
  - 检查是否拥有任一所需权限码 → 有则放行，无则抛 403

### 2.3 异常过滤器（filters/）

#### AllExceptionsFilter — 全局异常过滤器

文件路径：`apps/server/src/common/filters/all-exceptions.filter.ts`

**核心设计原则**：Service/Guard/Strategy 层 throw 时只传 i18n key，Filter 层根据 `Accept-Language` 请求头统一翻译。

执行流程：

```
异常抛出
  → 判断异常类型
    → HttpException → 提取 status 和 message
      → message 为数组 → class-validator 校验错误 → 替换为 'common.paramsError'
      → message 为字符串 → 直接使用（i18n key）
    → 其他异常 → status=500, message='common.serverError'
  → 读取 Accept-Language 请求头
  → translate(message, lang) → 加载 messages.json → 展平 key → 翻译
  → 返回 { code: status, message: 翻译后文案, data: null }
```

翻译文件加载策略：优先 `dist/i18n/`，回退 `src/i18n/`，支持 zh-CN / en-US，fallback 为 zh-CN。

### 2.4 拦截器（interceptors/）

#### TransformInterceptor — 统一响应拦截器

文件路径：`apps/server/src/common/interceptors/transform.interceptor.ts`

- 将 Controller 返回值包装为 `{ code: 200, message: 'success', data }`
- 通过 `@SkipTransform()` 装饰器可跳过包装（如文件下载等场景）

### 2.5 PrismaService — 数据库服务

文件路径：`apps/server/src/prisma/prisma.service.ts`

- 继承 `PrismaClient`，实现 `OnModuleInit` / `OnModuleDestroy`
- 全局模块，注入后可直接在 Service 中使用 `this.prisma.xxx`

## 3. AuthModule — 认证模块

文件路径：`apps/server/src/modules/auth/`

### 3.1 模块结构

```
auth/
├── auth.module.ts              # 模块定义
├── auth.controller.ts           # 认证接口
├── auth.service.ts             # 认证业务逻辑
├── auth-session.service.ts     # 会话持久化、轮换、撤销与重放检测
├── auth.constants.ts           # JWT 常量
├── dto/
│   ├── login.dto.ts             # 登录请求 DTO
│   ├── refresh-token.dto.ts     # 刷新 Token DTO
│   ├── update-profile.dto.ts    # 更新当前用户昵称 DTO
│   └── update-password.dto.ts   # 修改当前用户密码 DTO
└── strategies/
    └── jwt.strategy.ts          # Passport JWT 策略
```

### 3.2 接口清单

| 方法 | 路径 | 认证 | 说明 |
|---|---|---|---|
| POST | `/api/auth/login` | 公开 | 登录，返回 accessToken + refreshToken |
| POST | `/api/auth/logout` | 已登录 | 撤销当前服务端会话并清除前端 Token |
| GET | `/api/auth/profile` | 已登录 | 获取当前用户信息 + 角色权限码 |
| PUT | `/api/auth/profile` | 已登录 | 更新当前用户昵称 |
| PUT | `/api/auth/password` | 已登录 | 验证当前密码后修改密码并撤销全部会话 |
| GET | `/api/auth/menus` | 已登录 | 获取当前用户的动态菜单树 |
| POST | `/api/auth/refresh` | 公开(需refreshToken) | 校验会话并轮换 accessToken + refreshToken |

### 3.3 核心逻辑

#### 登录（login）

1. 根据 username 查询 AdminUser（含角色状态）
2. bcrypt.compare 验证密码
3. 检查用户状态（status=0 → 禁用）
4. 检查角色状态（所有角色均禁用 → 拒绝登录）
5. 创建 admin_session，签发含 sub/username/sid/jti/type/scope 的双 Token
6. 保存 Refresh Token 的 SHA-256 哈希，并在同一事务更新 lastLoginAt 和 lastLoginIp
7. 返回 `{ accessToken, refreshToken, expiresIn }`

#### Token 刷新（refresh）

1. 验证 refreshToken 签名、type、scope 和 sid
2. 检查固定会话有效期、撤销状态、用户状态和角色状态
3. 原子轮换双 Token 及数据库哈希，旧 Token 重放则撤销会话
4. 返回 `{ accessToken, refreshToken, expiresIn }`

Access Token 每次请求由 JwtStrategy 校验会话。个人改密、管理员重置密码和禁用用户会撤销该用户全部会话；登出只撤销当前会话。

#### 获取用户信息（getProfile）

1. 查询用户 + 启用角色 + 角色权限
2. 提取角色编码列表 `roles[]`
3. 提取权限码集合 `permissions[]`（去重）
4. 返回 `{ id, username, nickname, avatar, roles, permissions }`

#### 获取动态菜单（getMenus）

1. 查询用户启用角色的编码列表
2. **超级管理员**：查询所有 `type=1, visible=1` 的权限
3. **普通用户**：查询角色关联的 `type=1, visible=1` 权限
4. 追加 `menu.profile`（个人中心，所有用户默认可访问）
5. 按 parentId 构建菜单树

### 3.4 JWT 策略

文件路径：`apps/server/src/modules/auth/strategies/jwt.strategy.ts`

- 从 `Authorization: Bearer xxx` 头提取 token
- 验证签名 + type=access
- 返回 JwtPayload 挂载到 `request.user`

### 3.5 常量定义

```typescript
AUTH_CONSTANTS = {
  JWT_STRATEGY: 'jwt',
  TOKEN_TYPE_ACCESS: 'access',
  TOKEN_TYPE_REFRESH: 'refresh',
  SCOPE_ADMIN: 'admin',
  SCOPE_MEMBER: 'member',  // 预留
}
```

### 5.3 设计说明

- 会员管理**独立于 RBAC 体系**，不涉及角色和权限
- Member 表已具备 C端认证所需字段（password/status/lastLoginAt），后续扩展 C端认证无需额外建表
- 会员 JWT 使用独立密钥签发，与后台管理员 JWT 完全隔离（预留设计）

## 7. i18n — 后端多语言

文件路径：`apps/server/src/i18n/`

## 9. 种子数据

文件路径：`apps/server/prisma/seed.ts`

种子数据初始化内容：

1. **超级管理员**：`admin` / `admin123`（bcrypt 加密）
2. **角色**：超级管理员（`super_admin`）、运营专员（`operator`）
3. **权限菜单**：
   - 工作台（`menu.dashboard`）
   - 系统管理（`menu.system`）→ 后台用户 / 角色管理 / 权限管理 + 各自按钮权限
   - 个人中心（`menu.profile`，所有用户默认可访问）
   - 会员管理（`menu.member`）→ 会员列表 + 编辑/删除按钮权限
4. **关联**：super_admin 角色关联所有权限，admin 用户关联 super_admin 角色
