# Admin Template — 系统设计文档

> 本文档为 Admin Template 后台管理系统模板的完整设计规格，涵盖项目概述、数据库设计、后端 API、前后端架构、共享类型、种子数据与关键流程时序图。内容已与实际代码实现对齐。

## 1. 项目概述

### 1.1 项目目标

搭建一个可复用的后台管理系统模板，包含登录认证、RBAC 权限控制、会员管理、后台用户管理四大核心功能模块，作为后续业务系统的基础脚手架。

### 1.2 技术栈

| 前端框架 | Vue 3 + TypeScript | 3.4+ |

### 2.2 Prisma Schema 定义

```prisma
// Generator & DataSource
generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "mysql"
  url      = env("DATABASE_URL")
}

// ============ 后台用户管理 ============

/// 后台管理员用户
model AdminUser {
  id           Int              @id @default(autoincrement())
  username     String           @unique @db.VarChar(50)    // 登录用户名
  password     String           @db.VarChar(255)           // bcrypt 加密密码
  nickname     String           @db.VarChar(50)            // 昵称
  email        String?          @unique @db.VarChar(100)   // 邮箱
  phone        String?          @db.VarChar(20)            // 手机号
  avatar       String?          @db.VarChar(500)           // 头像URL
  status       Int              @default(1) @db.TinyInt    // 0=禁用 1=启用
  lastLoginAt DateTime?                                    // 最后登录时间
  lastLoginIp  String?          @db.VarChar(50)            // 最后登录IP
  remark       String?          @db.VarChar(500)           // 备注
  roles        AdminUserRole[]
  createdAt    DateTime         @default(now()) @map("created_at")
  updatedAt    DateTime         @updatedAt @map("updated_at")

  @@map("admin_user")
}

/// 角色
model Role {
  id          Int              @id @default(autoincrement())
  name        String           @unique @db.VarChar(50)    // 角色名称
  code        String           @unique @db.VarChar(50)    // 角色编码（如 super_admin）
  sort        Int              @default(0)                 // 排序
  status      Int              @default(1) @db.TinyInt    // 0=禁用 1=启用
  remark      String?          @db.VarChar(500)            // 备注
  users       AdminUserRole[]
  permissions RolePermission[]
  createdAt   DateTime         @default(now()) @map("created_at")
  updatedAt   DateTime         @updatedAt @map("updated_at")

  @@map("role")
}

/// 权限（菜单/按钮/API，树形结构）
model Permission {
  id          Int              @id @default(autoincrement())
  parentId    Int              @default(0) @map("parent_id")  // 父ID，0=根节点
  name        String           @db.VarChar(100)   // 权限名称，存i18n key
  type        Int              @db.TinyInt         // 1=菜单 2=按钮 3=API
  permission  String?          @db.VarChar(100)   // 权限标识
  path        String?          @db.VarChar(200)   // 前端路由路径
  component   String?          @db.VarChar(200)   // 前端组件路径
  icon        String?          @db.VarChar(50)    // 菜单图标
  sort        Int              @default(0)         // 排序
  visible     Int              @default(1) @db.TinyInt // 0=隐藏 1=显示
  roles       RolePermission[]
  createdAt   DateTime         @default(now()) @map("created_at")
  updatedAt   DateTime         @updatedAt @map("updated_at")

  @@map("permission")
}

/// 用户-角色关联
model AdminUserRole {
  id        Int  @id @default(autoincrement())
  userId    Int  @map("user_id")
  roleId    Int  @map("role_id")
  user      AdminUser @relation(fields: [userId], references: [id], onDelete: Cascade)
  role      Role      @relation(fields: [roleId], references: [id], onDelete: Cascade)

  @@unique([userId, roleId])
  @@map("admin_user_role")
}

/// 角色-权限关联
model RolePermission {
  id           Int         @id @default(autoincrement())
  roleId       Int         @map("role_id")
  permissionId Int         @map("permission_id")
  role         Role        @relation(fields: [roleId], references: [id], onDelete: Cascade)
  permission   Permission  @relation(fields: [permissionId], references: [id], onDelete: Cascade)

  @@unique([roleId, permissionId])
  @@map("role_permission")
}

// ============ 会员管理 ============

/// 前台会员
model Member {
  id           Int       @id @default(autoincrement())
  username     String?   @unique @db.VarChar(50)
  nickname     String?   @db.VarChar(50)
  phone        String?   @unique @db.VarChar(20)
  email        String?   @unique @db.VarChar(100)
  avatar       String?   @db.VarChar(500)
  password     String    @db.VarChar(255)           // 密码（bcrypt）
  gender       Int?      @db.TinyInt                // 0=未知 1=男 2=女
  status       Int       @default(1) @db.TinyInt
  lastLoginAt  DateTime?
  lastLoginIp  String?   @db.VarChar(50)
  remark       String?   @db.VarChar(500)
  createdAt    DateTime  @default(now()) @map("created_at")
  updatedAt    DateTime  @updatedAt @map("updated_at")

  @@map("member")
}

// 注：Member 表已有 password、status、lastLoginAt 等字段，
// C端认证直接复用本表，无需新增表。
// 会员 JWT 使用独立密钥签发，与后台管理员 JWT 完全隔离。
```

## 3. 后端 API 设计

### 3.1 统一响应格式

```typescript
// 成功响应
{
  "code": 200,
  "message": "success",
  "data": { ... }
}

// 分页响应
{
  "code": 200,
  "message": "success",
  "data": {
    "list": [...],
    "total": 100,
    "page": 1,
    "pageSize": 10
  }
}

// 错误响应
{
  "code": 401,
  "message": "登录已过期，请重新登录",
  "data": null
}
```

### 3.2 错误码定义

| 错误码 | 说明 |

## 4. 后端设计

### 4.1 认证机制

采用 **双 Token** 策略：

```
登录成功
  ├── accessToken  (有效期 2 小时，放在请求头 Authorization: Bearer xxx)
  └── refreshToken (有效期 7 天，存在本地，用于刷新 accessToken)

accessToken 过期
  ├── 前端拦截 401 响应
  ├── 用 refreshToken 调用 /api/auth/refresh
  ├── 获取并保存新的 accessToken + refreshToken
  └── 重发原始请求
```

**JWT Payload 结构：**

```typescript
// accessToken payload
{
  "sub": 1,           // userId
  "username": "admin",
  "sid": "会话 UUID",
  "jti": "Token UUID",
  "type": "access",    // token 类型
  "scope": "admin"     // 作用域
}

// refreshToken payload
{
  "sub": 1,
  "sid": "会话 UUID",
  "jti": "Token UUID",
  "type": "refresh",
  "scope": "admin"
}
```

管理员会话保存在 `admin_session`，Refresh Token 仅保存 SHA-256 哈希并在刷新时轮换；旧 Token 重放、登出、改密、重置密码和禁用用户会撤销对应会话。会话固定 7 天过期，刷新不延长；Access Token 每次请求校验会话和用户状态。

**C端会员 JWT [预留]：** 双 JWT 隔离——管理员和会员使用独立密钥，互不通用。

| | 管理员 JWT | 会员 JWT [预留] |
|---|---|---|
| 密钥环境变量 | `JWT_SECRET` | `JWT_MEMBER_SECRET` |
| accessToken 有效期 | 2h | 7d |
| refreshToken 有效期 | 7d | 30d |
| payload.scope | `"admin"` | `"member"` |

### 4.2 权限守卫机制

后端权限校验采用 **Guard + Decorator** 模式，全局注册在 `AppModule` 中：

```typescript
// 使用示例：
@Get('admin-users')
@UseGuards(JwtAuthGuard, PermissionGuard)  // JWT认证 + 权限校验（全局已注册，可省略）
@RequirePermission('system:user:view')      // 声明所需权限码
async findAll() { ... }

// 公开接口：
@Public()   // 标记为公开，跳过JWT守卫
@Post('login')
async login() { ... }
```

**权限守卫执行流程：**

```
请求进入
  → JwtAuthGuard: 验证 Authorization 头中的 accessToken
    → 有 @Public() → 放行
    → 失败: 返回 401
    → 成功: 将 user 信息挂载到 request 上
  → PermissionGuard: 读取 @RequirePermission 装饰器的权限码
    → 无装饰器: 直接放行
    → 有装饰器: 查询用户角色和权限码
      → super_admin 角色: 直接放行
      → 包含所需权限码: 放行
      → 不包含: 返回 403
```

   → isLogin()（localStorage 有 token）

       → 无 → userStore.info() 获取用户信息

   → menuFromServer 模式：检查目标是否在服务端菜单中

### 5.5 请求拦截器（`api/interceptor.ts`）

```
请求拦截: 自动添加 Authorization: Bearer {token} + Accept-Language: {当前语言}

响应拦截:
  → 200 + code 200: 返回响应信封中的 data（业务数据 T）
  → 200 + code != 200: Message.error 提示
    → code=401 且非登录接口 → 跳转登录页
  → HTTP 401:
    → 登录接口 → 提示，交给组件
    → 其他接口 → 尝试 refreshToken 刷新（每个请求最多重试一次）
      → isRefreshing → 并发请求排队
      → 刷新成功 → 重发原始请求
      → 刷新失败 → 跳转登录页
  → HTTP 403: Message.error 提示无权限
  → 其他: Message.error 提示
```

**并发刷新处理**：使用 `isRefreshing` 标志和 `pendingRequests` 队列，确保多个请求同时 401 时只刷新一次。业务 API 通过 `httpClient` 直接返回业务数据 `T`，刷新接口使用独立 Axios 实例。

## 8. 关键流程时序图

### 8.1 登录流程

```
前端                    后端                     数据库
  |                       |                        |
  |-- POST /auth/login -->|                        |
  |                       |-- 查询 admin_user ----->|
  |                       |<-- 返回用户记录 --------|
  |                       |                        |
  |                       |-- bcrypt.compare()     |
  |                       |-- 检查用户/角色状态     |
  |                       |-- 生成 accessToken     |
  |                       |-- 生成 refreshToken     |
  |                       |-- 更新 lastLoginAt --->|
  |                       |                        |
  |<-- { tokens } --------|                        |
  |                       |                        |
  |-- 存储 token          |                        |
  |-- GET /auth/profile ->|                        |
  |                       |-- 查询 user+roles ---->|
  |                       |<-- 返回权限列表 --------|
  |<-- { userInfo, perms }|                        |
  |                       |                        |
  |-- GET /auth/menus --->|                        |
  |                       |-- 查询 permissions --->|
  |                       |<-- 返回菜单树 ----------|
  |<-- { menus } ---------|                        |
  |                       |                        |
  |-- 注册动态路由        |                        |
  |-- 跳转 /dashboard     |                        |
```

### 8.2 Token 刷新流程

```
前端                    后端
  |                       |
  |-- 请求某接口 -------->|
  |                       |
  |<-- 401 Unauthorized --|  (accessToken 过期)
  |                       |
  |-- 拦截401             |
  |-- POST /auth/refresh->|  (携带 refreshToken)
  |                       |-- 验证 refreshToken
  |                       |-- 生成新 accessToken
  |                       |
  |<-- { new token } ----|
  |                       |
  |-- 重发原始请求 ------->|
  |<-- 响应数据 ----------|
```

**并发处理**：多个请求同时 401 时，通过 `isRefreshing` 标志确保只刷新一次，其他请求排队等待。

### 8.3 权限校验流程

```
前端                    后端Guard              数据库
  |                       |                      |
  |-- GET /admin-users -->|                      |
  |   (Bearer token)      |                      |
  |                       |                      |
  |                  JwtAuthGuard                 |
  |                  |-- 读取 @Public()           |
  |                  |-- 解析JWT                 |
  |                  |-- 验证签名                 |
  |                  |-- 挂载 request.user       |
  |                       |                      |
  |               PermissionGuard                 |
  |               |-- 读取 @RequirePermission    |
  |               |   → 'system:user:view'       |
  |               |-- 查询用户角色 ------------->|
  |               |<-- 返回角色编码列表 ----------|
  |               |-- super_admin? → 放行         |
  |               |-- 查询用户权限 ------------->|
  |               |<-- 返回权限码列表 ------------|
  |               |-- 检查 'system:user:view'   |
  |               |   是否在用户权限列表中        |
  |                       |                      |
  |               通过 → 放行                    |
  |               不通过 → 403 Forbidden         |
  |                       |                      |
  |<-- 响应数据 ----------|                      |
```
