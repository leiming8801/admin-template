# 认证与权限设计

> 本文档完整说明 Admin Template 的认证机制（JWT 双 Token）和权限体系（RBAC）的全链路设计，涵盖后端守卫机制、前端路由/按钮权限控制、Token 刷新流程等。

## 1. 认证机制 — JWT 双 Token

### 1.1 设计概要

采用 **双 Token + 服务端会话** 策略，兼顾安全性与用户体验。`admin_session` 保存会话固定过期时间、撤销状态和当前 Refresh Token 的 SHA-256 哈希，不保存 Token 明文：

| Token | 用途 | 有效期 | 存储 | 使用方式 |
|---|---|---|---|---|
| accessToken | API 请求认证 | 2h | 前端 localStorage | 请求头 `Authorization: Bearer {token}` |
| refreshToken | 刷新并轮换双 Token | 会话固定 7d | 前端 localStorage；后端仅保存 SHA-256 哈希 | 仅用于 `POST /api/admin/auth/refresh` |

### 1.2 JWT Payload 结构

```typescript
// accessToken payload
{
  sub: 1,              // 用户 ID
  username: "admin",   // 用户名
  sid: "会话 UUID",    // 服务端 admin_session.id
  jti: "Token UUID",   // 单次 Token ID
  type: "access",      // Token 类型
  scope: "admin"       // 作用域（admin / member）
}

// refreshToken payload
{
  sub: 1,
  username: "",
  sid: "会话 UUID",
  jti: "Token UUID",   // 每次轮换重新生成
  type: "refresh",
  scope: "admin"
}
```

### 1.3 密钥隔离

| | 管理员 JWT | 会员 JWT（预留） |
|---|---|---|
| 密钥环境变量 | `JWT_SECRET` | `JWT_MEMBER_SECRET` |
| refresh 密钥 | `JWT_REFRESH_SECRET` | `JWT_MEMBER_REFRESH_SECRET` |
| accessToken 有效期 | 2h | 7d |
| refreshToken 有效期 | 7d | 30d |
| payload.scope | `"admin"` | `"member"` |
| 可调接口 | `/api/admin/auth/*` `/api/admin/system/*` `/api/admin/members/*` `/api/admin/dashboard/*` | `/api/app/*`（预留） |

**隔离规则**：管理员 token 调 C端 API → 401，会员 token 调后台 API → 401。

### 1.4 登录流程

```
前端                        后端                       数据库
  |                           |                          |
  |-- POST /api/admin/auth/login -->|                          |
  |   { username, password }  |                          |
  |                           |-- 查询 admin_user ------>|
  |                           |   (含角色状态)            |
  |                           |<-- 返回用户记录 ---------|
  |                           |                          |
  |                           |-- bcrypt.compare()       |
  |                           |   验证密码                |
  |                           |                          |
  |                           |-- 检查用户状态            |
  |                           |   status=0 → 禁用         |
  |                           |-- 检查角色状态            |
  |                           |   所有角色禁用 → 拒绝      |
  |                           |                          |
  |                           |-- 生成带 sid 的双 Token  |
  |                           |-- 创建 admin_session ---->|
  |                           |   (仅保存 refresh 哈希)   |
  |                           |-- 更新 lastLoginAt ----->|
  |                           |   lastLoginIp            |
  |                           |                          |
  |<-- { accessToken,        |                          |
  |      refreshToken,        |                          |
  |      expiresIn } --------|                          |
  |                           |                          |
  |-- 存储 token 到 localStorage                        |
  |-- 跳转路由（触发守卫）                                |
  |   → 获取用户信息 + 动态菜单                           |
  |-- 跳转 /dashboard       |                          |
```

### 1.5 Token 刷新流程

```
前端                        后端
  |                           |
  |-- 请求某接口 -------------->|
  |   (Bearer accessToken)     |
  |                           |
  |<-- 401 Unauthorized -------|  (accessToken 过期)
  |                           |
  |-- Axios 拦截器拦截 401     |
  |                           |
  |-- POST /api/admin/auth/refresh ->|
  |   { refreshToken }         |
  |                           |-- 验证签名/type/scope/sid
  |                           |-- 检查会话、用户和角色状态
  |                           |-- 比对当前 Token 哈希并轮换
  |                           |   旧 Token 重放 → 撤销会话
  |                           |
  |<-- { accessToken,         |
  |      refreshToken,        |
  |      expiresIn } ---------|
  |                           |
  |-- 同时替换本地双 Token    |
  |-- 重发原始请求 ------------>|
  |<-- 响应数据 ---------------|
```

**并发请求处理**：

```
请求A → 401 → isRefreshing=true → 开始刷新 token
请求B → 401 → isRefreshing=true → 加入 pendingRequests 队列
请求C → 401 → isRefreshing=true → 加入 pendingRequests 队列

token 刷新成功
  → 通知 pendingRequests 队列（传入新 token）
  → 请求B、C 用新 token 重发

token 刷新失败
  → 通知 pendingRequests 队列（传入 null）
  → 所有请求 reject
  → 清除 token → 跳转登录页
```

### 1.6 登出与会话撤销

后端 `POST /api/admin/auth/logout` 根据 Access Token 的 `sid` 和 `sub` 撤销当前会话，前端随后清除 localStorage 和 Store。会话过期时间固定为登录后 7 天，刷新不会无限延长。

个人改密撤销当前用户全部会话，前端直接返回登录页；管理员重置密码、禁用用户也会撤销该用户全部会话。Access Token 每次请求都会校验会话、用户和角色状态，因此撤销后不能继续访问接口。旧版本 Token 不含 `sid`，升级后需重新登录。

## 2. 后端权限守卫机制

### 2.1 全局守卫注册

在 `app.module.ts` 中注册了两个全局守卫，按顺序执行：

```typescript
providers: [
  { provide: APP_GUARD, useClass: JwtAuthGuard },       // 1. JWT 认证
  { provide: APP_GUARD, useClass: PermissionGuard },     // 2. 权限校验
]
```

### 2.2 JwtAuthGuard — JWT 认证守卫

文件路径：`apps/server/src/common/guards/jwt-auth.guard.ts`

```
请求进入
  → Reflector 读取 @Public() 元数据
    → 有 @Public() → 直接放行（跳过认证）
    → 无 @Public() → 调用 Passport JWT 策略
      → 从 Authorization: Bearer xxx 提取 token
      → 验证签名 + type === 'access' + scope === 'admin'
      → 根据 sid 校验会话有效期、撤销状态、用户和角色状态
      → 成功 → 挂载 request.user (JwtPayload) → 放行
      → 失败 → 抛 UnauthorizedException('auth.tokenExpired')
```

### 2.3 PermissionGuard — 权限守卫

文件路径：`apps/server/src/common/guards/permission.guard.ts`

```
请求进入（JWT 认证已通过）
  → Reflector 读取 @RequirePermission() 元数据
    → 无装饰器 → 直接放行
    → 有装饰器 → 获取权限码列表
      → 从 request.user.sub 获取 userId
      → 查询用户角色编码列表
        → 包含 'super_admin' → 直接放行（超级管理员短路）
      → 查询用户权限码列表（通过角色关联权限）
      → 检查是否拥有任一所需权限码
        → 有 → 放行
        → 无 → 抛 ForbiddenException('auth.noPermission')
```

### 2.4 装饰器使用示例

```typescript
// 公开接口（不需要认证）
@Public()
@Post('login')
async login() { ... }

// 需要认证 + 特定权限
@Get('admin-users')
@RequirePermission('system:user:view')
async findAll() { ... }

// 需要认证 + 多个权限码（满足任一即可）
@Delete('admin-users/:id')
@RequirePermission('system:user:delete')
async remove() { ... }

// 需要认证但不需要特定权限码
@Get('dashboard/stats')
async getStats() { ... }  // 有 JwtAuthGuard 但无 @RequirePermission → 放行

// 获取当前登录用户
@Get('profile')
async getProfile(@CurrentUser() user: JwtPayload) {
  // user.sub, user.username, user.sid, user.type, user.scope
}
```

## 3. 前端权限控制

### 3.1 路由级权限 — 路由守卫

文件路径：`apps/web/src/hooks/permission.ts` + `apps/web/src/router/guard/permission.ts`

`usePermission().accessRouter(route)` 校验逻辑：

```
accessRouter(route)
  → route.meta.requiresAuth === false → 放行（如登录页）
  → route.meta.roles 包含 '*' → 放行（所有角色可访问）
  → isSuperAdmin() → 放行（super_admin 短路）
  → route.meta.roles 有值 → 检查用户角色是否匹配
    → 匹配 → 放行
    → 不匹配 → 无权限
  → route.meta.requiresPermission 有值 → 检查用户权限码
    → 包含 → 放行
    → 不包含 → 无权限
  → 无限制 → 放行
```

在 `menuFromServer` 模式下，权限守卫还会检查目标路由是否在服务端返回的菜单中：

```
目标路由
  → 菜单未加载 → fetchServerMenuConfig()
  → 在服务端菜单中 + 有权限 → 放行
  → 不在菜单中或无权限 → 跳转 404
```

### 3.2 按钮级权限 — v-permission 指令

文件路径：`apps/web/src/directive/permission/index.ts`

```vue
<!-- 单个权限码：需要 system:user:add 权限 -->
<a-button v-permission="'system:user:add'" @click="handleAdd">
  新增
</a-button>

<!-- 多个权限码：满足任一即可 -->
<a-button v-permission="['system:user:edit', 'system:user:delete']">
  更多操作
</a-button>
```

执行逻辑：

```
mounted / updated 钩子
  → 读取指令绑定的权限码（string | string[]）
  → userStore.roles 包含 'super_admin' → 通过（超级管理员短路）
  → 检查是否拥有任一所需权限码
    → 有 → 保留元素
    → 无 → el.parentNode.removeChild(el)（从 DOM 移除）
```

### 3.3 编程式权限检查

```typescript
// 在组件中使用
const userStore = useUserStore();
const Permission = usePermission();

// 检查权限码
if (userStore.hasPermission('system:user:add')) { ... }
// 或
if (Permission.hasPermission('system:user:add')) { ... }

// hasPermission 逻辑：
// super_admin → true
// 其他角色 → permissions.includes(code)
```

### 3.4 动态菜单与路由注册

文件路径：`apps/web/src/utils/menu-to-route.ts` + `apps/web/src/store/modules/app/index.ts`

```
登录成功 → 路由守卫触发
  → userStore.info() → GET /api/admin/auth/profile → 获取 roles + permissions
  → appStore.fetchServerMenuConfig() → GET /api/admin/auth/menus → 获取菜单树
  → transformMenusToRoutes(menus) → 菜单树转 Vue Router 路由
  → router.addRoute(route) → 动态注册每条路由
  → next({ path: to.fullPath, replace: true }) → 重新导航确保路由生效
```

**菜单转路由映射**：

| 菜单字段 | 路由字段 |
|---|---|
| `path` | `route.path` |
| `component`（如 `system/admin-user/index`） | `route.component` = `import.meta.glob('@/views/**/*.vue')['/src/views/system/admin-user/index.vue']` |
| `name`（i18n key） | `route.meta.locale`（前端 `t()` 翻译） |
| `icon` | `route.meta.icon` |
| `children` | `route.children`（递归转换） |

## 5. 超级管理员特殊处理

`super_admin` 角色在以下所有位置均绕过权限校验：

| 位置 | 文件 | 逻辑 |
|---|---|---|
| 后端 PermissionGuard | `permission.guard.ts` | `userRoles.includes('super_admin')` → 直接放行 |
| 后端 AuthService.getMenus() | `auth.service.ts` | 查询所有菜单权限而非按角色过滤 |
| 前端 useUserStore.hasPermission() | `store/modules/user/index.ts` | `roles.includes('super_admin')` → return true |
| 前端 usePermission.accessRouter() | `hooks/permission.ts` | `isSuperAdmin()` → return true |
| 前端 v-permission 指令 | `directive/permission/index.ts` | `roles.includes('super_admin')` → 保留元素 |

## 6. 异常响应与权限错误

### 6.1 后端异常 → i18n 翻译

Service / Guard / Strategy 层 throw 时只传 i18n key，由 `AllExceptionsFilter` 统一翻译：

| 场景 | 抛出 | i18n key | 中文翻译 |
|---|---|---|---|
| 用户名或密码错误 | `UnauthorizedException('auth.loginFailed')` | `auth.loginFailed` | 用户名或密码错误 |
| Token 过期/无效 | `UnauthorizedException('auth.tokenExpired')` | `auth.tokenExpired` | 登录已过期，请重新登录 |
| 账号禁用 | `UnauthorizedException('auth.accountDisabled')` | `auth.accountDisabled` | 账号已禁用，请联系管理员 |
| 角色禁用 | `UnauthorizedException('auth.roleDisabled')` | `auth.roleDisabled` | 所属角色已被禁用，请联系管理员 |
| 刷新令牌无效 | `UnauthorizedException('auth.refreshTokenInvalid')` | `auth.refreshTokenInvalid` | 刷新令牌无效，请重新登录 |
| Refresh Token 重放 | `UnauthorizedException('auth.refreshTokenReused')` | `auth.refreshTokenReused` | 检测到登录状态异常，请重新登录 |
| 会话撤销或过期 | `UnauthorizedException('auth.sessionInvalid')` | `auth.sessionInvalid` | 登录会话已失效，请重新登录 |
| 当前密码不正确 | `BadRequestException('auth.oldPasswordIncorrect')` | `auth.oldPasswordIncorrect` | 当前密码不正确 |
| 新旧密码相同 | `BadRequestException('auth.newPasswordSame')` | `auth.newPasswordSame` | 新密码不能与当前密码相同 |
| 无权限 | `ForbiddenException('auth.noPermission')` | `auth.noPermission` | 无权限访问 |
| 参数校验错误 | class-validator 数组 → `'common.paramsError'` | `common.paramsError` | 参数错误 |
| 服务器错误 | 其他异常 → `'common.serverError'` | `common.serverError` | 服务器内部错误 |

### 6.2 前端错误处理

| HTTP 状态 | 处理 |
|---|---|
| 200 + code 200 | 返回 data |
| 200 + code 401（非登录接口） | 跳转登录页 |
| 200 + code != 200 | Message.error 提示 |
| HTTP 401（非登录接口） | 尝试 refreshToken 轮换双 Token，每个请求最多重试一次 |
| HTTP 401（登录接口） | Message.error 提示，交给组件 |
| HTTP 403 | Message.error 提示无权限 |
| 其他 | Message.error 提示 |

## 7. C端会员认证（预留设计）

> 以下为预留设计，当前模板阶段不实现。Member 表已具备 C端认证所需字段。

### 7.1 三种认证级别

| 装饰器 / Guard | 认证级别 | 无 token | 有 token 但无效 |
|---|---|---|---|
| `@Public()` | 公开 | 放行 | 放行 |
| `@UseGuards(MemberAuthGuard)` | 必须登录 | 401 | 401 |
| `@UseGuards(OptionalMemberAuthGuard)` | 可选登录 | 放行 (user=null) | 401 |

### 7.2 预留接口

| 方法 | 路径 | 认证级别 | 说明 |
|---|---|---|---|
| POST | `/api/app/auth/register` | 公开 | 会员注册 |
| POST | `/api/app/auth/login` | 公开 | 会员登录，返回 Member JWT |
| POST | `/api/app/auth/refresh` | 公开(需refreshToken) | 刷新会员 accessToken |
| GET | `/api/app/profile` | 必须登录 | 获取当前会员信息 |
| PUT | `/api/app/profile` | 必须登录 | 修改个人信息 |
| GET | `/api/app/products` | 公开 | 商品列表（无需登录） |
| GET | `/api/app/products/:id` | 可选登录 | 商品详情（登录后返回个性化数据） |

### 7.3 OptionalMemberAuthGuard 执行流程（预留）

```
请求进入 → 提取 Authorization 头
  → 无 token → request.user = null → 放行
  → 有 token → 验证签名 + 检查 scope === "member"
    → 有效 → request.user = 会员信息 → 放行
    → 无效/过期 → 返回 401（带了 token 就该校验）
```
