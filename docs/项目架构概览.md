# 项目架构概览

> 本文档从全局视角介绍 Admin Template 的整体架构、模块关系与核心数据流，帮助快速建立项目全貌认知。

## 1. 架构定位

Admin Template 是一个**前后端分离的 Monorepo 后台管理系统模板**，定位为业务系统的基础脚手架。核心交付四大能力：

| 能力 | 说明 |
|---|---|
| 登录认证 | JWT 双 Token（accessToken + refreshToken），无感刷新 |
| RBAC 权限控制 | 用户-角色-权限三级关联，菜单/按钮/API 三粒度 |
| 后台用户管理 | 管理员 CRUD、角色分配、密码重置、状态管理 |
| 会员管理 | C端会员数据维护，独立于 RBAC 体系 |

## 2. Monorepo 结构

项目采用 pnpm workspace + turbo 管理多包：

```
admin-template/
├── apps/
│   ├── server/        # NestJS 后端服务
│   └── web/           # Vue3 前端应用
├── packages/
│   └── shared/        # 前后端共享 TypeScript 类型定义
├── docker-compose.yml # 容器编排（MySQL + Server + Web）
├── turbo.json         # turbo 构建任务定义
└── pnpm-workspace.yaml
```

**包依赖关系**：

```
apps/web ────────依赖────────→ @admin-template/shared
apps/server ─────依赖────────→ @admin-template/shared
```

- 前端通过 Vite alias 直接引用 shared 源码（`packages/shared/src/index.ts`），无需编译
- 后端通过 `workspace:*` 引用 shared 编译产物（`dist/`），需先 `pnpm build`

## 3. 后端架构（NestJS）

### 3.1 分层结构

```
src/
├── common/                # 横切关注点（全局生效）
│   ├── decorators/       #   自定义装饰器
│   ├── filters/          #   全局异常过滤器
│   ├── guards/           #   全局守卫
│   ├── interceptors/     #   全局响应拦截器
│   └── utils/            #   工具函数
├── config/               # 环境变量配置
├── i18n/                 # 后端多语言资源
├── modules/              # 业务模块
│   ├── auth/             #   认证模块
│   ├── system/           #   系统管理模块
│   │   ├── admin-user/   #     后台用户子模块
│   │   ├── role/         #     角色子模块
│   │   └── permission/   #     权限子模块
│   ├── member/           #   会员管理模块
│   └── dashboard/        #   工作台统计模块
├── prisma/               # PrismaClient 全局服务
├── app.module.ts         # 根模块（注册全局组件 + 业务模块）
└── main.ts              # 启动入口
```

### 3.2 全局组件注册

在 `app.module.ts` 中注册了三个全局组件：

| 组件 | 类型 | 作用 |
|---|---|---|
| `AllExceptionsFilter` | APP_FILTER | 捕获所有异常，按 `Accept-Language` 翻译 i18n key，统一响应格式 |
| `JwtAuthGuard` | APP_GUARD | 全局 JWT 认证守卫，默认所有接口需认证，`@Public()` 跳过 |
| `PermissionGuard` | APP_GUARD | 全局权限守卫，配合 `@RequirePermission` 校验权限码 |

在 `main.ts` 中注册了：

| 组件 | 作用 |
|---|---|
| CORS | 允许前端跨域访问 |
| 全局前缀 `api` | 所有路由以 `/api` 开头 |
| ValidationPipe | 自动校验 DTO，whitelist + transform |
| TransformInterceptor | 包装返回值为 `{ code, message, data }` |
| Swagger | `/docs` 路径提供 API 文档 |

### 3.3 模块职责

| 模块 | 路由前缀 | 职责 |
|---|---|---|
| AuthModule | `/api/auth` | 登录、Token 刷新、用户信息、动态菜单 |
| SystemModule | `/api/system/*` | 后台用户 CRUD、角色 CRUD、权限树管理 |
| MemberModule | `/api/members` | 会员列表、详情、编辑、状态管理、删除 |
| DashboardModule | `/api/dashboard` | 工作台统计数据 |
| PrismaModule | - | 全局 PrismaClient 注入 |

### 4.2 核心数据流

#### 登录 → 首页渲染全链路

```
用户输入账号密码
  → store/user.login() 调用 POST /api/auth/login
  → 后端 AuthService.login() 验证密码 → 签发 accessToken + refreshToken
  → 前端 store token 到 localStorage
  → 路由守卫 userLoginInfoGuard 拦截
  → store/user.info() 调用 GET /api/auth/profile → 获取角色 + 权限码
  → appStore.fetchServerMenuConfig() 调用 GET /api/auth/menus → 获取菜单树
  → utils/menu-to-route.ts 将菜单转为 Vue Router 路由
  → router.addRoute() 动态注册
  → 跳转 /dashboard
```

#### Token 自动刷新流程

```
任意 API 请求 → 后端返回 401（accessToken 过期）
  → Axios 响应拦截器拦截 401
  → 判断是否为登录/刷新接口 → 是则交给组件处理
  → 否则用 refreshToken 调用 POST /api/auth/refresh
  → 成功 → 更新 accessToken → 重发原始请求
  → 失败 → 清除 token → 跳转登录页
  → 并发请求排队等待刷新结果（isRefreshing + pendingRequests）
```

## 6. 共享类型包

`packages/shared` 统一管理前后端共享的 TypeScript 类型：

| 文件 | 核心类型 |
|---|---|
| `common.ts` | `ApiResponse<T>`、`PageQuery`、`PageResult<T>`、`StatusEnum`、`PermissionTypeEnum` |
| `auth.ts` | `LoginRequest`、`LoginResult`、`RefreshTokenResult`、`UserProfile`、`MenuItem` |
| `system.ts` | `AdminUser`、`Role`、`Permission`、`RoleListItem` 及各 DTO |
| `member.ts` | `Member`、`MemberDto`、`MemberQuery` |
| `dashboard.ts` | `DashboardStats` |

详见 [共享类型包说明](./共享类型包说明.md)。

## 7. 架构设计原则

1. **接口默认安全**：全局 JWT 守卫 + 权限守卫，所有接口默认需要认证和权限，公开接口用 `@Public()` 显式标记
2. **i18n key 而非硬编码文案**：异常 throw 时传 i18n key（如 `auth.loginFailed`），由全局过滤器统一翻译
3. **前后端类型一致**：共享类型包确保接口契约一致，编译时类型安全
4. **动态路由而非静态注册**：菜单从后端获取，按权限过滤后动态注册，实现灵活的权限控制
5. **无感 Token 刷新**：accessToken 过期自动刷新，并发请求排队等待，用户无感知
6. **超级管理员短路**：`super_admin` 角色在前后端均绕过权限校验，简化超级管理员的使用体验
