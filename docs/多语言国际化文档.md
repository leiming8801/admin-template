# 多语言国际化文档

> 本文档说明 Admin Template 前后端多语言（i18n）的实现方案、文件结构、翻译约定与语言切换机制。

## 1. 整体方案

Admin Template 实现了**前后端全链路多语言**，支持中文（zh-CN）和英文（en-US）：

| 层 | 技术 | 语言判断方式 |
|---|---|---|
| 前端 | vue-i18n 9+ | localStorage `arco-locale` |
| 后端 | nestjs-i18n 10+ | 请求头 `Accept-Language` |
| UI 组件库 | Arco Design ConfigProvider | 跟随前端 locale |
| 表格组件 | VxeTable setLanguage | 跟随前端 locale |

**核心同步机制**：前端 Axios 请求拦截器自动在每个请求头中注入 `Accept-Language: {当前语言}`，确保后端返回对应语言的错误消息。

### 2.2 i18n 实例

文件路径：`apps/web/src/locale/index.ts`

```typescript
import { createI18n } from 'vue-i18n';
import en from './en-US';
import cn from './zh-CN';

export const LOCALE_OPTIONS = [
  { label: '中文', value: 'zh-CN' },
  { label: 'English', value: 'en-US' },
];

const defaultLocale = localStorage.getItem('arco-locale') || 'zh-CN';

const i18n = createI18n({
  locale: defaultLocale,        // 当前语言
  fallbackLocale: 'en-US',      // 回退语言
  legacy: false,                 // 使用 Composition API 模式
  allowComposition: true,
  messages: { 'en-US': en, 'zh-CN': cn },
});
```

### 2.5 语言切换

文件路径：`apps/web/src/hooks/locale.ts`

```typescript
export default function useLocale() {
  const i18 = useI18n();

  const changeLocale = (value: string) => {
    if (i18.locale.value === value) return;
    i18.locale.value = value;                          // 1. 更新 vue-i18n locale
    localStorage.setItem('arco-locale', value);          // 2. 持久化
    VxeUI.setLanguage(value as 'zh-CN' | 'en-US');      // 3. 同步 VxeTable
    Message.success(i18.t('navbar.action.locale'));      // 4. 提示
  };

  return { currentLocale, changeLocale };
}
```

**切换后自动生效的组件**：

| 组件 | 同步方式 | 文件 |
|---|---|---|
| vue-i18n | `i18n.locale.value = value` | `hooks/locale.ts` |
| Arco Design | `<a-config-provider :locale="arcoLocale">` 响应式 | `App.vue` |
| VxeTable | `VxeUI.setLanguage(value)` | `hooks/locale.ts` |
| 后端 API | Axios 请求拦截器 `Accept-Language` 头 | `api/interceptor.ts` |
| 页面刷新保持 | `localStorage.getItem('arco-locale')` | `locale/index.ts` |

### 2.6 菜单名称翻译逻辑

后端返回的菜单 `name` 字段存储的是 i18n key（如 `menu.system.adminUser`），前端渲染时用 `t()` 翻译：

```typescript
// 菜单组件渲染
function renderMenuName(menu: MenuItem): string {
  return menu.name ? t(menu.name) : menu.name;
  // 如果 t() 找不到 key，vue-i18n 默认返回 key 本身，不影响显示
}
```

**自定义菜单**：管理员在权限管理页面直接输入显示名称（不写 i18n key），前端 `t()` 找不到翻译时直接显示原文，兼容自定义菜单。

### 2.7 组件中使用

<script setup>

## 3. 后端国际化

### 3.1 配置

文件路径：`apps/server/src/i18n/i18n.config.ts`

```typescript
import { I18nOptions, HeaderResolver } from 'nestjs-i18n';

export const i18nOptions: I18nOptions = {
  fallbackLanguage: 'zh-CN',
  loaderOptions: {
    path: findI18nPath(),  // 优先 dist/i18n/，回退 src/i18n/
    watch: false,
  },
  resolvers: [
    { use: HeaderResolver, options: ['zh-CN', 'en-US'] },
  ],
};
```

通过 `HeaderResolver` 读取请求头 `Accept-Language` 判断语言，支持 `zh-CN` / `en-US`，fallback 为 `zh-CN`。

### 3.4 异常过滤器中的翻译机制

文件路径：`apps/server/src/common/filters/all-exceptions.filter.ts`

**核心设计原则**：Service / Guard / Strategy 层 throw 时只传 i18n key，Filter 层统一翻译。

```
异常抛出（如 throw new UnauthorizedException('auth.loginFailed')）
  → AllExceptionsFilter.catch()
    → 提取 exception message（i18n key）
    → 读取 request.headers['accept-language']
    → translate('auth.loginFailed', 'zh-CN')
      → loadTranslations('zh-CN')
        → 加载 messages.json → flattenKeys() 展平为 dot key
        → 结果: { 'auth.loginFailed': '用户名或密码错误', ... }
      → 查找 translations['zh-CN']['auth.loginFailed']
      → 找到 → 返回 '用户名或密码错误'
      → 未找到 → fallback 到 zh-CN → 仍未找到 → 返回 key 本身
    → 返回 { code: 401, message: '用户名或密码错误', data: null }
```

**翻译缓存**：`translations` 对象按语言目录缓存已加载的翻译，避免重复读取文件。

**展平逻辑**：将嵌套 JSON `{ auth: { loginFailed: "..." } }` 展平为 `{ 'auth.loginFailed': "..." }`。

### 3.5 异常消息约定

| 场景 | 抛出方式 | i18n key |
|---|---|---|
| 认证失败 | `throw new UnauthorizedException('auth.xxx')` | `auth.*` |
| 权限不足 | `throw new ForbiddenException('auth.noPermission')` | `auth.noPermission` |
| 资源不存在 | `throw new NotFoundException('system.role.notFound')` | `system.*.notFound` |
| 唯一约束冲突 | `throw new ConflictException('system.role.nameExists')` | `system.*.nameExists` |
| 参数校验错误 | class-validator 自动抛出（message 为数组） | `common.paramsError` |
| 其他未知异常 | - | `common.serverError` |

### 3.6 添加新翻译的步骤

1. 在 `src/i18n/zh-CN/messages.json` 中添加 key + 中文翻译
2. 在 `src/i18n/en-US/messages.json` 中添加相同 key + 英文翻译
3. 在 Service / Guard 中 `throw new XxxException('your.i18n.key')`

## 4. 前后端语言同步

### 4.1 请求拦截器自动注入

文件路径：`apps/web/src/api/interceptor.ts`

```typescript
httpInstance.interceptors.request.use((config) => {
  const token = getToken();
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  // 自动注入当前语言
  config.headers['Accept-Language'] = i18n.global.locale.value;
  return config;
});
```

每个业务请求都会自动携带 `Accept-Language` 头，值与前端当前语言一致。后端 `HeaderResolver` 读取此头返回对应语言的翻译。

### 4.2 语言切换后的全链路同步

```
用户点击语言切换按钮
  → useLocale.changeLocale('en-US')
    → i18n.locale.value = 'en-US'         → 前端文案立即切换
    → localStorage.setItem('arco-locale', 'en-US')  → 持久化
    → VxeUI.setLanguage('en-US')           → 表格组件切换
    → 后续请求自动携带 Accept-Language: en-US  → 后端错误消息切换
    → 页面刷新后从 localStorage 读取 → 保持语言
```

## 5. 新增多语言文案的检查清单

### 前端新增文案

- [ ] 在对应页面的 `locale/zh-CN.ts` 和 `locale/en-US.ts` 中添加 key
- [ ] 在 `locale/zh-CN.ts` 和 `locale/en-US.ts` 聚合文件中导入（新页面时）
- [ ] 使用 `$t('key')` 或 `t('key')` 在组件中引用

### 后端新增异常消息

- [ ] 在 `src/i18n/zh-CN/messages.json` 中添加 key + 中文
- [ ] 在 `src/i18n/en-US/messages.json` 中添加 key + 英文
- [ ] 在 Service / Guard 中 throw 时使用 i18n key
- [ ] **不要**在 throw 时传硬编码中文文案

### 新增菜单项

- [ ] 在 `seed.ts` 中添加权限定义，`name` 字段使用 i18n key（如 `menu.yourModule`）
- [ ] 在前端 `locale/zh-CN.ts` 和 `en-US.ts` 中添加对应的菜单翻译 key
- [ ] 执行 `pnpm db:seed` 更新种子数据
