# 部署与运维指南

> 本文档说明 Admin Template 的本地开发环境搭建、Docker 容器化部署、Nginx 配置与生产环境运维注意事项。

## 1. 本地开发环境

### 1.1 环境要求

| 依赖 | 最低版本 | 说明 |
|---|---|---|
| Node.js | 18.0.0+ | 由 `package.json` engines 声明 |
| pnpm | 9.0.0+ | 包管理器（`packageManager: pnpm@9.15.0`） |
| MySQL | 8.0+ | 数据库（可使用 Docker 启动） |

### 1.2 搭建步骤

```bash
# 1. 克隆项目
git clone <repo-url>
cd admin-template

# 2. 安装依赖
pnpm install

# 3. 配置环境变量
cp .env.example apps/server/.env
# 编辑 apps/server/.env，设置 JWT_SECRET、JWT_REFRESH_SECRET 等

# 4. 启动 MySQL（可选，使用 Docker）
docker compose up mysql -d

# 5. 创建数据库
mysql -u root -p -e "CREATE DATABASE admin_template CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"

# 6. 执行数据库迁移（全新数据库）
pnpm db:migrate:deploy

# 7. 生成 Prisma Client
pnpm db:generate

# 8. 填充种子数据
pnpm db:seed

# 9. 启动开发服务
pnpm dev
```

### 1.3 开发服务地址

| 服务 | 地址 |
|---|---|
| 前端 | http://localhost:5173 |
| 后端 API | http://localhost:3000/api |
| Swagger 文档 | http://localhost:3000/docs |

### 1.4 前端开发代理

前端开发时 `VITE_API_BASE_URL` 为空（见 `.env.development`），使用 Vite 开发代理转发 API 请求到后端。Vite 配置在 `config/vite.config.dev.ts` 中设置代理规则。直连后端时该变量填写服务源地址（如 `http://localhost:3000`），不要追加 `/api`。

### 1.5 端口冲突处理

如果端口 3000 或 5173 被占用：

```bash
# Windows
netstat -ano | findstr :3000
taskkill /PID <PID> /F

# 或使用 npx
npx kill-port 3000 5173
```

## 2. Docker 容器化部署

### 2.1 docker-compose.yml 服务编排

文件路径：`docker-compose.yml`

| 服务 | 镜像 | 端口 | 说明 |
|---|---|---|---|
| `mysql` | `mysql:8.0` | 3306 | MySQL 数据库，utf8mb4 字符集 |
| `server` | 本地构建 | 3000 | NestJS 后端，依赖 mysql |
| `web` | 本地构建 | 80 | Vue3 前端（Nginx 托管），依赖 server |

### 2.2 后端 Dockerfile（多阶段构建）

文件路径：`apps/server/Dockerfile`

```
阶段一：builder（node:18-alpine）
  → 安装 pnpm
  → 拷贝 workspace 配置 + package.json + pnpm-lock.yaml
  → pnpm install --frozen-lockfile
  → 拷贝源码
  → 生成 Prisma Client
  → 构建 shared 包 → 构建 server 包

阶段二：runner（node:18-alpine）
  → 安装 pnpm
  → 拷贝编译产物（dist/）+ package.json + prisma/
  → pnpm install --prod（仅生产依赖）
  → 拷贝 i18n 资源
  → EXPOSE 3000
  → CMD ["node", "apps/server/dist/main.js"]
```

**构建产物说明**：
- `dist/main.js` — 后端入口
- `dist/i18n/` — i18n 翻译文件（`messages.json`），由 `copyfiles` 在构建时拷贝

### 2.3 前端 Dockerfile（多阶段构建）

文件路径：`apps/web/Dockerfile`

```
阶段一：builder（node:18-alpine）
  → 安装 pnpm
  → 拷贝 workspace 配置 + package.json + pnpm-lock.yaml
  → pnpm install --frozen-lockfile
  → 拷贝源码
  → 构建 shared 包 → 构建 web 包（vite build）

阶段二：runner（nginx:alpine）
  → 拷贝 dist/ 到 nginx html 目录
  → 拷贝 nginx.conf
  → EXPOSE 80
  → CMD ["nginx", "-g", "daemon off;"]
```

### 2.4 Nginx 配置

文件路径：`apps/web/nginx.conf`

```nginx
server {
    listen 80;
    server_name localhost;

    root /usr/share/nginx/html;
    index index.html;

    # Vue Router history 模式：SPA 回退
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 后端 API 代理：转发到 server 容器
    location /api/ {
        proxy_pass http://server:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # gzip 压缩
    gzip on;
    gzip_types text/plain text/css application/json application/javascript
               text/xml application/xml text/javascript image/svg+xml;
    gzip_min_length 1024;
}
```

**关键配置**：
- `try_files $uri $uri/ /index.html` — Vue Router history 模式回退，刷新页面不 404
- `proxy_pass http://server:3000` — 通过 Docker 网络别名 `server` 转发 API 请求
- gzip 压缩减少传输体积

### 2.5 .dockerignore

文件路径：`.dockerignore`

排除以下文件不进入 Docker 构建上下文：

```
node_modules / **/node_modules    # 依赖目录（构建时重新安装）
dist / **/dist                     # 构建产物（构建时重新生成）
.turbo / **/.turbo                 # turbo 缓存
*.log                              # 日志文件
.git / .gitignore                  # Git 元数据
.env / .env.* / !.env.example      # 环境变量（通过 docker-compose 注入）
README.md / AGENTS.md / docs       # 文档
```

### 2.6 构建与启动

```bash
# 构建并启动所有服务
docker compose up -d

# 查看服务状态
docker compose ps

# 查看日志
docker compose logs -f server
docker compose logs -f web

# 停止所有服务
docker compose down

# 停止并删除数据卷（清空数据库）
docker compose down -v
```

### 2.7 生产环境环境变量

在 `docker-compose.yml` 中，后端从 `apps/server/.env` 读取密钥等配置，并通过 `environment` 覆盖容器运行参数：

```yaml
env_file:
  - apps/server/.env
environment:
  NODE_ENV: production
  DATABASE_URL: 'mysql://user:password@mysql:3306/admin_template'
  JWT_ACCESS_EXPIRES: '2h'
  JWT_REFRESH_EXPIRES: '7d'
  PORT: 3000
```

**生产环境注意事项**：
- 将 `JWT_SECRET` 和 `JWT_REFRESH_SECRET` 替换为不同的强随机密钥，长度至少 32 字符；示例开发密钥会被拒绝
- 数据库密码修改为强密码
- 考虑使用 Docker secrets 或外部密钥管理

### 2.8 数据库初始化（Docker 环境）

在包含 Prisma CLI 的宿主机或 CI 中，从仓库根目录执行：

```bash
# 全新数据库执行已提交迁移；既有 db push 数据库先按 §5.5 基线化
pnpm db:migrate:deploy
pnpm db:generate

# 按需独立初始化种子数据
pnpm db:seed
```

宿主机的 `DATABASE_URL` 必须指向同一 MySQL：宿主机通常使用 `localhost:3306`，server 容器内使用 `mysql:3306`。生产运行镜像只安装生产依赖，不要依赖容器内 `npx prisma` 临时下载 CLI，也不要让每个应用副本启动时自动执行迁移。

```bash

pnpm db:migrate:status

# 开发环境生成并应用迁移
pnpm db:migrate:dev

# 执行已提交迁移
pnpm db:migrate:deploy

# 临时原型同步（不生成迁移，禁止用于生产）
```

## 5. 生产环境注意事项

### 5.1 安全

- **JWT 密钥**：生产环境必须将 `JWT_SECRET` 和 `JWT_REFRESH_SECRET` 替换为不同的强随机字符串，长度至少 32 字符，否则服务拒绝启动
- **数据库密码**：修改 MySQL root 密码为强密码
- **CORS**：生产环境应将 `CORS_ORIGIN` 设置为实际前端域名
- **HTTPS**：建议在 Nginx 前面配置 HTTPS（TLS 证书）
- **Swagger**：生产环境可考虑关闭 Swagger 文档或增加访问认证

### 5.2 性能

- **数据库连接池**：Prisma 默认连接池大小可根据并发量调整
- **Nginx gzip**：已启用 gzip 压缩，减少传输体积
- **前端构建优化**：Vite 生产构建已配置代码分割和压缩（见 `config/vite.config.prod.ts`）
- **静态资源缓存**：可在 Nginx 中为静态资源添加缓存头

### 5.3 持久化

- **数据库数据**：`mysql_data` Docker volume 持久化数据库文件
- **上传文件**：本地文件写入 `apps/server/storage/uploads/`，容器部署必须将该目录挂载为持久化 volume；当前实现不依赖 COS

### 5.4 日志

- 后端日志：NestJS Logger 输出到 stdout，Docker 可通过 `docker compose logs` 查看
- 前端日志：浏览器控制台
- 异常日志：`AllExceptionsFilter` 中 `this.logger.error()` 记录未处理异常

### 5.5 数据库迁移

迁移文件统一保存在 `apps/server/prisma/migrations/` 并提交 Git。`0_init` 是初始迁移，`20261112000000_add_admin_sessions` 新增后台认证会话表，`20261112122039_add_file_object` 新增本地文件元数据表。

**开发环境新增结构变更**：

```bash
# 根据 Schema 生成并应用迁移，同时更新 Prisma Client
pnpm db:migrate:dev

# 检查状态并提交生成的迁移文件
pnpm db:migrate:status
```

**全新数据库 / 测试 / 生产环境**：在包含 Prisma CLI 的开发、CI 或迁移环境执行：

```bash
# 先执行已提交且尚未应用的迁移，再启动依赖新表的新版本服务
pnpm db:migrate:deploy

# 按需独立执行，不由 migrate deploy 自动触发
pnpm db:seed
```

**既有 `db push` 数据库基线化（仅一次）**：已有表不能直接重复执行 `0_init`。先备份并确认当前连接的是目标数据库，再做只读 drift 核对：

```bash
# 退出码 0 表示结构一致；退出码 2 表示存在 drift，必须停止并人工处理
pnpm --dir apps/server exec prisma migrate diff --from-schema-datasource prisma/schema.prisma --to-schema-datamodel prisma/schema.prisma --exit-code
```

仅在 drift 核对为空后，将初始迁移登记为已应用。该命令会写 `_prisma_migrations` 迁移历史，但不会重跑 `0_init` 的建表 SQL：

```bash
pnpm --dir apps/server exec prisma migrate resolve --applied 0_init
pnpm db:migrate:status
```

空库不要执行 `migrate resolve`，直接使用 `db:migrate:deploy`。认证会话版本升级时必须先应用 `20261112000000_add_admin_sessions`，再启动新后端；旧 Token 不含 `sid`，升级后所有后台用户需要重新登录。如果数据库包含不属于 Prisma Schema 的其他业务表，应先隔离数据库或明确维护策略，不要为了消除 drift 直接删除这些表。禁止使用 `prisma migrate reset` 或 `db push --force-reset` 解决正常升级或 drift。

## 6. 常见问题

### Q: 数据库连接失败？

检查 `DATABASE_URL` 格式：`mysql://用户名:密码@主机:端口/数据库名`。Docker 环境中主机名为 `mysql`，本地开发为 `localhost`。

### Q: 前端请求后端 404？

检查前端 `VITE_API_BASE_URL` 配置。开发环境为空（使用 Vite 代理），生产环境通过 Nginx 代理 `/api/` 到 `server:3000`。

### Q: 种子数据执行报错？

确保数据库已创建（`CREATE DATABASE admin_template ...`），且 `pnpm db:migrate:deploy` 已执行成功；既有 `db push` 数据库需先按 §5.5 基线化。

### Q: Docker 构建缓慢？

首次构建需要下载基础镜像和安装依赖。`.dockerignore` 已排除 `node_modules` 和 `dist`，避免拷贝不必要文件。修改代码后使用 `docker compose build` 增量构建。

### Q: 修改了共享类型后后端不生效？

修改 `packages/shared/src/` 后需执行 `pnpm build --filter=@admin-template/shared` 重新编译，后端引用的是 `dist/` 产物。前端通过 Vite alias 直接引用源码，无需编译。
